시놀로지 NAS 배포 안내 — DS216+II / DSM 6.2.4-25556

이 NAS에서는 아래 'DSM 6 설치' 절차를 먼저 사용하세요.
Container Manager의 프로젝트 메뉴는 DSM 7용 안내이며 DSM 6에는 없습니다.

DSM 6 설치 (현재 사용자 환경)
패키지 센터에서 Docker를 설치합니다.
outputs/synology-homepage.zip을 NAS에 올리고 아래 폴더에 압축 해제합니다.
예: /volume1/docker/argo-homepage
Dockerfile이 해당 폴더 바로 아래에 있는지 확인합니다.

DSM 제어판 > 터미널 및 SNMP에서 SSH 서비스를 활성화한 후,
PC 터미널에서 관리자 계정으로 접속합니다. NAS_IP와 관리자계정은 실제 값으로 바꾸세요.
ssh 관리자계정@NAS_IP
cd /volume1/docker/argo-homepage

먼저 아래 명령으로 구형 DSM의 Docker에서 Node.js가 실행되는지 확인합니다.
sudo docker run --rm node:22-bookworm-slim node -e "const {DatabaseSync}=require('node:sqlite'); const db=new DatabaseSync(':memory:'); console.log(process.version, db.prepare('SELECT 1 AS ok').get()); db.close()"
버전과 ok: 1이 출력되면 빌드/실행을 진행합니다.
Illegal instruction, Operation not permitted, 커널/라이브러리 오류 등이 나오면
전체 앱 설치를 중단하고 출력된 오류를 확인해야 합니다.
이 앱은 Node 22.16 이상 및 node:sqlite를 사용하므로 DSM의 구형 Node 패키지로
그냥 교체해서 실행할 수 없습니다. Docker도 NAS의 커널을 공유합니다.
Node 22의 공식 Linux x64 지원 기준은 커널 4.18 이상입니다.
구형 커널은 실행될 수도 있으나 지원/작동을 보장할 수 없습니다.

sudo docker build -t argo-homepage:local .
sudo docker volume create argo-homepage-data
sudo docker run -d --name argo-homepage --restart unless-stopped -p 8080:3000 -v argo-homepage-data:/var/data argo-homepage:local
sudo docker logs --tail 100 argo-homepage

이후 http://NAS_IP:8080 으로 접속합니다. index.html을 붙이지 않습니다.
Docker 앱의 컨테이너 목록에서도 실행 상태와 로그를 볼 수 있습니다.
8080을 이미 사용 중이면 -p 8081:3000 등으로 바꾸고 접속 포트도 바꾸세요.
NAS에 메모리가 부족해 빌드가 종료되면 Linux amd64 Docker 환경이 있는 PC에서
이미지를 빌드해 docker save로 내보낸 뒤 DSM Docker의 이미지 가져오기로 옮길 수 있습니다.
현재 배포 ZIP은 소스이며 사전 빌드된 Docker 이미지가 아닙니다.

로그인을 설정할 때는 아래 3절을 참고해 .env를 만들고,
최초 docker run 명령에 --env-file .env 옵션을 추가하세요.
예: sudo docker run -d --name argo-homepage --restart unless-stopped --env-file .env -p 8080:3000 -v argo-homepage-data:/var/data argo-homepage:local
이미 실행 중인 같은 이름의 컨테이너가 있으면 새 명령은 실패합니다.
설정을 바꿀 때는 기존 컨테이너를 중지하고 컨테이너만 삭제한 다음 위 명령으로
재생성합니다. argo-homepage-data 볼륨은 유지하고 같은 볼륨을 다시 연결하세요.
.env의 NAS_HTTP_PORT는 Compose 전용입니다. 위 직접 실행에서는 -p 값을 바꾸세요.
DSM 6의 역방향 프록시는 제어판 > 응용 프로그램 포털 > 역방향 프록시에 있습니다.
아래 4절의 소스/대상 값으로 연결하세요.

1. index.html이 없는 이유
첫 화면 소스는 app/page.tsx입니다. 이 프로젝트는 Next.js 호환 Vinext 서버가
HTML을 생성합니다. 빌드 결과 dist/client만 Web Station에 복사하거나
page.tsx를 index.html로 변경하면 로그인·게시판·DB 기능이 작동하지 않습니다.
현재 홈페이지 전체 기능은 Node.js 서버로 실행해야 합니다.

2. DSM 7 Container Manager용 설치 (참고, 현재 DSM 6에서는 위 절차 사용)
Container Manager를 지원하는 NAS가 필요합니다. 패키지 센터에서 설치하세요.
DSM 버전과 모델에 따라 지원 여부가 다릅니다.

제공된 outputs/synology-homepage.zip을 NAS의 폴더에 압축 해제합니다.
예: /volume1/docker/argo-homepage
압축 안의 Dockerfile과 docker-compose.yml이 이 폴더 바로 아래에 있어야 합니다.
직접 소스를 복사해도 됩니다. app, public, scripts, drizzle, .openai 등
소스 폴더와 package-lock.json을 포함하세요. .openai/hosting.json도 필요합니다.
PC용 node_modules, .sites-runtime, dist와 .dev.vars는 복사할 필요가 없습니다.

Container Manager > 프로젝트 > 생성:
- 프로젝트 이름: argo-homepage
- 경로: 위에서 압축을 해제한 폴더
- 소스: 기존 docker-compose.yml 사용
- 빌드 및 시작을 선택합니다.
처음에는 인터넷에서 Node 이미지와 npm 패키지를 받아 빌드하므로 시간이 걸립니다.
서버가 실행되면 브라우저에서 http://NAS의내부IP:8080 으로 접속합니다.
index.html 경로나 /home 경로를 붙이지 않습니다.
기본 8080 포트를 이미 사용 중이라면 아래 .env의 NAS_HTTP_PORT를 바꾸세요.
연결이 안 되면 컨테이너 로그와 DSM 방화벽의 해당 포트 허용 여부를 확인하세요.
http://NAS의내부IP:8080/api/health 에서 status: ok를 확인할 수 있습니다.

3. 환경변수와 로그인
synology.env.example을 같은 폴더의 .env라는 이름으로 복사한 뒤 수정합니다.
일반 홈페이지와 공개 게시판은 Google 키 없이도 열립니다.
Google 로그인·회원가입·회원 Q&A에는 아래 설정이 필요합니다.

NAS_HTTP_PORT=8080
APP_ORIGIN=https://사용할도메인
AUTH_SECRET=무작위로생성한32자이상문자열
GOOGLE_CLIENT_ID=발급받은값
GOOGLE_CLIENT_SECRET=발급받은값
NAVER_MAP_CLIENT_ID=지도키가있으면입력
VINEXT_TRUSTED_HOSTS=사용할도메인

AUTH_SECRET은 Node.js가 설치된 컴퓨터에서 다음 명령으로 생성할 수 있습니다.
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
Google OAuth 승인된 리디렉션 URI:
https://사용할도메인/auth/google/callback
기존 호스팅의 키가 자동으로 NAS에 옮겨지지는 않습니다.
내부망 HTTP IP 주소에서는 홈페이지·공개 게시판을 확인하고,
Google 로그인은 HTTPS 도메인 연결 후 설정하세요. LOGIN-MAP-SETUP.txt도 참고하세요.
.env를 바꾼 뒤에는 프로젝트를 다시 생성/배포하여 컨테이너에 반영하세요.
단순 프로세스 재시작만으로는 변경된 환경변수가 적용되지 않을 수 있습니다.

4. 도메인 연결
DSM 제어판 > 로그인 포털 > 고급 > 역방향 프록시에서 다음처럼 연결합니다.
- 소스: HTTPS, 사용할 도메인, 443
- 대상: HTTP, 127.0.0.1, 8080 (NAS_HTTP_PORT를 바꿨다면 변경한 값)
해당 도메인의 인증서를 적용하고 DNS가 NAS를 가리키도록 설정합니다.
공유기 밖에서 접속한다면 공유기에서도 HTTPS 연결을 NAS로 전달해야 합니다.
홈페이지는 도메인의 루트(/)에 연결하세요. /home 같은 하위 경로는 지원하지 않습니다.
VINEXT_TRUSTED_HOSTS에는 위 소스 도메인만 입력합니다.

5. 저장 데이터와 업데이트
회원·방명록·게시판 DB는 Docker 볼륨 homepage-data의 /var/data/argo.sqlite에 저장됩니다.
컨테이너 재시작·재빌드 시 동일한 프로젝트와 볼륨을 유지하세요.
볼륨 삭제 또는 docker compose down -v는 저장된 DB를 삭제하므로 사용하지 마세요.
백업은 프로젝트를 중지한 상태에서 해당 볼륨 전체를 보관하세요.
기존 Render/Sites 게시판 데이터는 이 설치로 자동 이전되지 않습니다.
MSDS 작업 자료는 기존처럼 각 방문자의 브라우저 IndexedDB에 저장됩니다.
주소가 바뀌면 기존 브라우저 저장 자료도 자동 이전되지 않습니다.

6. SSH에서 실행하는 경우 (선택)
프로젝트 폴더에서:
docker compose up -d --build
docker compose logs -f homepage
이전 Docker 패키지에서는 docker-compose 명령을 사용할 수도 있습니다.

Container Manager/Docker를 지원하지 않는 모델이라면 이 구성을 직접 실행할 수 없습니다.
그 경우에는 NAS 모델과 DSM 버전을 확인하여 다른 Node.js 실행 환경을 준비하거나,
별도 정적 소개 홈페이지로 변환할 범위를 정해야 합니다.

검증 범위: Windows에서 동일한 Node 서버 빌드와 런타임 검증을 통과했습니다.
실제 NAS 및 Docker 이미지 실행은 이 PC에서 확인할 수 없습니다.
